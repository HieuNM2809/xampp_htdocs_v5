Phần 7/7 — Testing approach

Pragmatic — chia 3 lớp: tự động, debug tools, playtest tay

1. Unit tests

physics + entity logic

  • Vitest (chạy nhanh, ESM ngon)
  • Test AABB collision: trên/dưới/trái/phải
  • Test variable-jump physics
  • Test state transition Player: small→big→fire→big→small→dead
  • Test Koopa: walk → stomp → shell → kicked
  • ~15-25 test, không cần canvas/DOM
2. Debug overlay

F1/F2/F3 trong khi chơi

  • F1: bật/tắt vẽ AABB của mọi entity
  • F2: FPS counter, số entity, vị trí player
  • F3: nhảy nhanh level (cycle 1→2→3→4)
  • F4: bất tử (god mode) — để playtest
  • Phát hiện ngay collision lệch, performance chậm
3. Playtest checklist

Tay người chơi

  • Hoàn thành mỗi màn từ đầu → cờ
  • Tất cả block tương tác đúng
  • Mọi power-up nhặt được
  • Boss đánh bại được, có thua được
  • Pause / resume / quit / retry không bug
  • HUD đúng, score lưu localStorage
  • Audio không bị stuck khi mute/unmute

🧪 Ví dụ unit test (physics)

// test/physics.test.js import { describe, it, expect } from 'vitest'; import { resolveCollision } from '../src/physics.js'; describe('AABB collision', () => { it('player rơi xuống ground → đứng yên trên ground', () => { const player = { x: 100, y: 200, w: 32, h: 32, vy: 300 }; const ground = { x: 0, y: 240, w: 500, h: 64 }; resolveCollision(player, ground, 0.016); expect(player.y + player.h).toBe(240); expect(player.vy).toBe(0); expect(player.onGround).toBe(true); }); it('player chạy ngang vào tường → dừng, vẫn rơi', () => { ... }); });

⚙️ Setup

  • package.json với dev-dep vitest (~13MB) — chạy npm test
  • Game chính không cần npm install — chỉ test cần
  • Không có e2e test (Playwright/Cypress) — overkill cho dự án học
  • CI không cần — đây là project học cá nhân

📋 Phạm vi YAGNI

  • ❌ Không test render (vẽ Canvas pixel-perfect khó test, ROI thấp)
  • ❌ Không test audio (chỉ test khi unmute SFX có gọi đúng, không test sóng)
  • ❌ Không snapshot test
  • ✅ Test logic thuần (physics, entity state, collision resolution) — đáng tiền nhất
